# Security

Do not report vulnerabilities or exposed credentials in a public issue. Contact the repository owner through a private channel; use GitHub private vulnerability reporting only if it has been enabled by the owner. Do not include secrets or personal data in issues, pull requests, logs, or test fixtures.

The current repository is a development scaffold and has not been approved for public deployment. The initial API and any generated previews must not be treated as authenticated until access controls are implemented and verified. Protect provider secrets server-side and restrict integration privileges.

Security reports should describe affected versions, steps to reproduce in an authorized environment, and impact without exposing other users’ data. The owner will determine remediation and disclosure timing.
